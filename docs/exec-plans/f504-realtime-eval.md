# F504 评估记录：Realtime 全双工语音接口（GLM-Realtime 类）

> 日期：2026-09-16 ｜ 结论：**现阶段不做**（观察项继续保留）
> 依据：开发方案 §5.1（全双工视频通话已被"三层反馈环"取代）；本特性验收口径为"产出评估记录并决策，不做也算完成"。

## 三指标评估

| 指标 | 评估 | 说明 |
|---|---|---|
| 延迟 | 未实测 | 端到端语音对话通常 1~2s 量级（公开资料口径）；本项目需求（手型点评播报）用系统 TTS 已 0 成本解决，无需低延迟双工 |
| 成本 | 未实测 | 实时语音接口按音频时长计费，显著高于文本链路；与用户"成本敏感、DeepSeek 优先"的既定偏好冲突 |
| 质量 | 未实测 | 语音识别+合成对吉他弹奏场景（强噪声/复音）收益有限；聊天问答（F101 已有文本链）+ 周复盘（F501）已覆盖核心诉求 |

**实测阻塞**：火山方舟账号尚未开通任何模型（`ModelNotOpen`，见 L007），Realtime 接口无法实测三指标。开通后若仍需评估，按 docs/模型API接入手册.md 的 curl 流程补测。

## 决策

**不做**。理由：三层反馈环（端侧规则 0ms + 关键帧点评 + 文本问答）已覆盖目标场景，实时双工的边际价值低、成本高、引入面大。feature_list 中该观察项保留 pending 状态，待方舟开通且有真实诉求再重启评估。
