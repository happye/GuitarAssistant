# 黄金原则

> 项目级铁律，每条都有事故或调研实证。违反 = 返工，无例外。

1. **音频是正确性的真相源**：视觉说"你按着 C"、音频说"听到 E"，以音频为准——单目摄像头判品物理上不可靠（开发方案 §5.4）
2. **不确定就直说，不编造**：提示词强制"看不清就说"，产品上单次点评 ≤2 条、高置信度才显示（误报伤信任比没反馈更糟）
3. **UI 层不直接碰网络/数据库/模型客户端**：一切经 data/AppContainer 的编排器与仓库
4. **所有外部调用必须有超时与失败降级**：模型 API（网关已有 400 降级、429 透出、备份链）、文件、数据库同理
5. **模型输出永远不可信**：JSON 解析判空容错；识谱结果过合法性过滤（弦 1-6 / 品 0-24）才入 TabDocument
6. **错误信息对用户可执行**："请到首页检查 API Key 配置"，不暴露堆栈与术语
7. **术语第一次出现必须有人话解释，给可执行动作不给空评价**："指尖垂直按在品丝后面"，不是"手指再立一点"（产品设计红线）
8. **识别与讲解分离**：识谱只产出结构化 TabDocument（可校验、可编辑、可回放），讲解基于结构化数据——避免每次重看图、每次讲得不一样
9. **默认用更便宜的模型**：先问"DeepSeek 能不能干"；成本控制内建于架构（压缩、限帧、显式思考参数），不靠事后省
10. **新功能必须有测试，验证靠跑不靠读**；每个里程碑以"自己真的会用"验收，曲库/社区/音效类功能一律后置（防范围蔓延）
